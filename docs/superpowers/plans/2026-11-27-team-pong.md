# Team Pong Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A TV-screen team pong played from phone browsers, served by a Node server on the laptop.

**Architecture:** The `/screen` page owns the game (physics, drawing, sound); the server only creates rooms and relays
JSON between the screen, phones and an optional `/host` page. All game logic lives in pure ES modules under
`public/` that both the browser and `node:test` import, so canvas/audio/touch glue stays thin.

**Tech Stack:** Node 24, `ws`, `qrcode`, vanilla JS (no build), `node:test` with coverage, Playwright (cached
browsers, `channel: 'chrome'`) for the end-to-end proof.

**Spec:** `docs/superpowers/specs/2026-11-27-team-pong-design.md`

## Global Constraints

- Code files under 200 lines; meaningful numbers and strings live once in `public/shared/constants.js` (server
  imports it too).
- `/screen` and every module it imports: no syntax or API newer than Chrome 69 (no `?.`, `??`, class fields,
  flex `gap`, `aspect-ratio`, `clamp()`, CSS nesting). Enforced by Task 6's `tests/es-level.test.js`. Phone and host
  pages may be modern.
- No third-party resources (CDN, Google Fonts); system fonts; sounds generated with WebAudio, no audio files.
- Room codes: 4 letters from `ABCDEFGHJKLMNPQRSTUVWXYZ` (no I, O).
- Teams `left` / `right`, max 4 players each; Start needs at least 1 per team.
- Teammate collision: push apart, flash, freeze 1000 ms, vibrate both phones.
- Phone input: at most 60 messages/s, only on change.
- Physics: fixed 60 Hz step with substeps; frame dt clamped (≤ 100 ms) so a stalled tab does not jump.
- Device-pixel ratio capped at 1.5.
- Coverage: `node --test --experimental-test-coverage --test-coverage-lines=90`; DOM glue files
  (`public/screen/main.js`, `public/phone/main.js`, `public/host/main.js`, `public/games/pong/render.js`,
  `public/games/pong/sound.js`) are excluded from coverage and proved by the end-to-end test instead.
- Every test task asserts its test count (`node --test` summary line `# tests N`).
- Customer-facing text (phone and screen wording) passes the `customer-words` skill before the PR.

## Review Focus

1. Tab backgrounded / rAF stalls → match clock runs on simulated time, dt clamped; no ball teleport. (Task 5 test)
2. Ball ends inside a rotating bat or pinned against a wall → ball is pushed out along the normal, never stuck for
   more than one step. (Task 4 test)
3. Malformed or oversized WebSocket messages (server may go public) → dropped silently, connection stays, messages
   over 1 KB rejected. (Task 2 test)
4. Phone locks / disconnects mid-match → its bat is removed; a team emptying pauses the match. (Task 5 test)
5. Touch scrolls, zooms or pulls-to-refresh the phone page → `touch-action: none`, `overscroll-behavior: none`,
   viewport `user-scalable=no`. (Task 3 e2e check)

## Message protocol (constants `MSG`)

| type | from → to | payload |
|---|---|---|
| `create` | screen → server | – ; reply `created {room}` |
| `join` | phone → server | `{room, name, team}`; reply `joined {id, color, isMaster}` or `error {reason}` |
| `host` | host → server | `{room}`; reply `joined {isMaster:true}` |
| `player` | server → screen | `{id, name, team, color}` (join) / `left {id}` |
| `input` | phone → screen | `{id, x, y, a}` x,y in 0..1 of own half, a radians |
| `settings` / `start` / `pause` / `end` / `again` | master → screen | `{mode:'time'|'score', value}` for settings |
| `role` | server → phone/host | `{isMaster}` |
| `buzz` | screen → one phone | `{id, ms}` |
| `state` | screen → all phones/host | `{phase, score, timeLeft, settings, canStart}` (on change only) |
| `closed` | server → phones | screen left |

### Task 3a: Control math — pad and bat (pure)

**Files:** `public/phone/pad.js`, `public/games/pong/bat.js`, `tests/pad.test.js`, `tests/bat.test.js`.

**Interfaces — Produces:**
- `createPad() → { down(px,py,w,h), move(px,py,w,h) → {x,y,a}, up() }` — x,y = touch / pad size (0..1, same
  orientation for both teams); angle changes by the signed turn of successive movement directions, ignoring
  segments shorter than `PAD_MIN_MOVE` (jitter), so a straight drag does not rotate and a full circle turns ≈ 2π.
- `createBat({id, team, color}) → bat`, `setTarget(bat, {x,y,a})`, `stepBat(bat, dt)` (ease toward target with
  `BAT_EASE_MS`, track `vx, vy, va`), `batEnds(bat) → [p1,p2]`; both ends clamped inside the team's half.

- [ ] Step 1: Failing tests: straight drag → a unchanged; clockwise circle of 32 points → a ≈ +2π (±0.2); anticlockwise
  → −2π; 0.5 px jitter → no change; target x=1 for the left team keeps the whole bat left of the centre line, also
  rotated 90°; easing reaches 95% of target within `BAT_EASE_MS`.
- [ ] Step 2: Implement. `npm test` → PASS, `# tests 21`. Commit `feat: pad and bat math`.

  both pushed apart, both `frozenUntil = now+1000`, frozen bats ignore targets but still deflect the ball.
- [ ] Step 2: Implement (circle vs. thick segment, push-out along normal). `npm test` → PASS, `# tests 32`.
